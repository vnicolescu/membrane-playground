# R3 – Quarantine, gatekeeping and impact assessment for agent-to-agent messages

**The answer to the key question, up front.** No: a gatekeeper that is itself an LLM cannot hold authority over text it reads, and the literature converges on this from four directions (design-pattern papers, adaptive-attack evaluations, attacks on LLM judges, and a production exploit that walked past a shipped classifier). What the literature does allow is a model as a **sensor with bounded, typed output that can only tighten** the boundary, sitting in front of a **deterministic gate that alone can release**. Release above a low impact tier belongs to an anchor, confirmed out of band over a hash of the sealed item. Section 2 gives the minimal architecture; section 5 the open problems.

## 1. Findings

**F1. Indirect prompt injection: data becomes instruction.** An LLM that reads retrieved content cannot reliably tell data from instructions, so anyone who can place text in its input can steer it: data theft, worming, ecosystem contamination, API manipulation. Shown on Bing Chat and code-completion engines. · Prevents: nothing; it names the threat that every agent-to-agent message carries by construction. · Cost of ignoring: every peer message is a remote control. · Greshake et al., arxiv.org/abs/2302.12173 (2023) · opened

**F2. The lethal trifecta and the Rule of Two.** Private data + untrusted content + external communication in one agent equals exfiltration on demand (Willison). Meta formalises it: per session an agent may hold at most two of [A] untrusted input, [B] sensitive data or systems, [C] state change or external communication; needing all three means no autonomy, supervision required. Willison calls a guardrail catching 95% of attacks a failing grade in security terms. · Prevents: exfiltration and hijacked actions, by removing a leg rather than detecting the attack. · Cost: capability loss; fresh sessions or human checkpoints for three-leg tasks. Meta says it is not a finish line. · simonwillison.net/2025/Jun/16/the-lethal-trifecta/ (2025) opened; ai.meta.com/blog/practical-ai-agent-security/ (2025) opened

**F3. The Dual LLM pattern – direct precedent for seed 1.** A privileged LLM sees only trusted input and holds tools; a quarantined LLM reads untrusted content, holds no tools, and is assumed to go rogue. A non-AI controller stores quarantined output under symbolic variables ($VAR1) so the privileged model handles references, never the tainted text. Willison himself flags the holes: users can be socially engineered into pasting outputs across, chaining LLMs re-opens the vector, and the plumbing is easy to leak. · Prevents: untrusted text reaching the model that holds authority. · Cost: complexity; the privileged side cannot reason over content it cannot see. · simonwillison.net/2023/Apr/25/dual-llm-pattern/ (2023) · opened

**F4. CaMeL – control flow from the trusted query, data flow from untrusted data, capabilities on values.** The privileged LLM writes a program from the user's request; a custom interpreter runs it; the quarantined LLM is called only to extract values into a fixed schema, with a boolean flag to say it lacks information instead of improvising. Every value carries metadata (provenance and allowed readers), and security policies are checked at each tool call. Result on AgentDojo: 77% of tasks solved with provable security vs 84% undefended. Explicitly out of scope: text-to-text attacks that only change what the output says (a lying summary), phishing of the user, side channels. In deployment, policy violations would go to user confirmation rather than hard block. · Prevents: injected data changing which actions run, and data flowing to readers not allowed to see it. · Cost: 7 points of utility, policy authoring, confirmation load. · Debenedetti et al., arxiv.org/abs/2503.18813 and /html (2025) · opened

**F5. FIDES – information-flow control with typed inspection.** Microsoft's planner attaches a product label (integrity: trusted/untrusted; confidentiality: reader sets) to every datum, hides any tool-result node whose label is more restrictive than the current context behind a fresh variable, and checks two deterministic policies at tool calls: consequential actions only from a trusted context; data egress only to recipients inside the data's reader set. Its sharpest idea for a gatekeeper: a quarantined inspection call whose output is constrained by a type lattice (bool below enum below string), so a boolean extracted from hostile text carries at most one bit of attacker payload and policy can admit it. Injections on gpt-4o fell from 163 to 1 with policies on. FIDES criticises human-in-the-loop prompts for confirmation fatigue and social engineering. · Prevents: injection-driven actions and label-violating egress, with the leak capacity of any model reading hostile text bounded by type. · Cost: utility drop (reported 24.5% for FIDES with reasoning models vs 40% for the basic planner under policy); label plumbing. · Costa, Köpf et al., arxiv.org/abs/2505.23643 and /html (2025) · opened

**F6. Six design patterns, and the verdict on detection.** Action-selector (LLM maps requests to a fixed menu of calls), plan-then-execute (action list fixed before any untrusted data is read), LLM map-reduce (isolated instances per item, constrained reduce), dual LLM, code-then-execute (CaMeL-style), context minimisation (drop content from context once it has done its job). The authors class input/output detectors as heuristic and unable to guarantee prevention, and doubt that general-purpose agents can offer reliable guarantees at all. · Prevents: untrusted input triggering consequential actions. · Cost: generality. · Beurer-Kellner et al., arxiv.org/abs/2506.08837 and /html (2025) · opened

**F7. Guards fail under adaptive attack – the empirical answer to the key question.** Twelve published jailbreak and prompt-injection defenses, most originally reporting near-zero attack success, were broken at above 90% for most by adaptive attacks (gradient, RL, search, human red-teaming). Willison's summary of the paper gives static attacks 0–62%, automated adaptive 71–100%, and a 500-person human red-team at 100% against every defense. · Prevents: nothing; it retires the claim that a trained filter is a boundary. · Nasr, Carlini, Sitawarin et al., arxiv.org/abs/2510.09023 (2025) opened; per-condition numbers from simonwillison.net/2025/Nov/2/new-prompt-injection-papers/ (2025) secondary

**F8. LLM judges are injectable.** JudgeDeceiver optimises a sequence inside an attacker-controlled candidate so an LLM-as-a-judge picks it regardless of rivals; known-answer and perplexity detection did not stop it (CCS 2024). A gatekeeper that ranks or scores inbound messages is a judge. · Shi et al., arxiv.org/abs/2403.17710 (2024) · opened (abstract); per-model success rates of about 88–99% come from the search snippet of the paper, secondary

**F9. Production evidence: EchoLeak (CVE-2025-32711, CVSS 9.3).** One crafted email to an M365 Copilot user exfiltrated context data with zero clicks. The chain bypassed Microsoft's cross-prompt-injection classifier by phrasing instructions as if addressed to the human recipient, then slipped past link redaction and content security policy. Authors recommend prompt partitioning, provenance-based access control and least privilege. · Lesson: a shipped model-based gate was beaten by register, not by optimisation. · Reddy & Gujral, arxiv.org/abs/2509.10540 (2025) opened; CVSS score and classifier-bypass detail secondary (Checkmarx, Cato, Willison pages via search)

**F10. Multi-agent contagion: Prompt Infection.** A malicious prompt self-replicates across connected agents, collapsing their roles into a loop that runs the payload. Stronger models resist first contact more (GPT-4o ignored 66% vs GPT-3.5's 9%) but, once compromised, spread the infection more precisely. LLM Tagging (prefixing agent-originated messages with their source) cut attacks by only about 5% alone; combined with marking it reached 0% in their (non-adaptive) tests. · Prevents: provenance confusion between user and peer. · Cost: cheap, but not a boundary. · Lee & Tiwari, arxiv.org/abs/2410.07283 and /html (2024) · opened

**F11. Epidemic threshold for agent swarms: Agent Smith.** One adversarial image in one agent's memory spreads jailbreak through up to a million LLaVA agents via random pairwise chat. The authors derive a provable containment condition: if defense makes infection rate β at most twice the recovery rate γ, infection goes to zero over time; how to build a practical defense meeting it stays open. · Prevents: framing error; the unit of defense is the population rate, not the single message. · Gu et al., arxiv.org/abs/2402.08567 and /html (ICML 2024) · opened

**F12. Worms through RAG email assistants: Morris II.** Adversarial self-replicating prompts cascade through GenAI email assistants, extracting data at each hop. Their "Virtual Donkey" detector reports TPR 1.0, FPR 0.015 – a non-adaptive evaluation that F7 suggests should not be read as a boundary. · Cohen, Bitton, Nassi, arxiv.org/abs/2403.02817 (2024) · opened

**F13. Orchestration-layer hijack survives per-agent robustness.** Adversarial web content or files hijack control flow in AutoGen, CrewAI and MetaGPT to run arbitrary code or exfiltrate, 58–90% of trials with GPT-4o depending on orchestrator, some configurations 100%, and it works even when each individual agent resists injection and refuses harmful actions. · Lesson: security cannot be a property of each agent's alignment; it must be a property of the channel and the gate. This independently confirms the deployed client channel's incident (guardrails inside an agent's own tool layer are advisory). · Triedman, Jha, Shmatikov, arxiv.org/abs/2503.12188 (2025) · opened

**F14. Agent-in-the-Middle.** An LLM-powered adversary that only intercepts and rewrites inter-agent messages, using reflection to fit role-restricted formats, can compromise whole multi-agent systems (DoS, steering). · Prevents (as argument): unauthenticated channels. · Cost of mitigation: signatures, message integrity. · He et al., arxiv.org/abs/2502.14847 (ACL Findings 2025) · opened

**F15. Tool poisoning, shadowing, rug pulls.** Hidden instructions in MCP tool descriptions (visible to the model, not the user) exfiltrate keys; a server can change descriptions after approval (rug pull); a malicious server can rewrite how a trusted server's tools are used (shadowing). Mitigations: show full descriptions, pin versions and checksums, isolate servers. · Maps to peer self-descriptions (agent cards, capability lists) in any A2A protocol. · Invariant Labs, invariantlabs.ai/blog/mcp-security-notification-tool-poisoning-attacks (2025) · opened

**F16. OWASP Top 10 for Agentic Applications (Dec 2025).** ASI01 goal hijack, ASI02 tool misuse, ASI03 identity and privilege abuse, ASI04 supply chain, ASI05 unexpected code execution, ASI06 memory and context poisoning, ASI07 insecure inter-agent communication, ASI08 cascading failures, ASI09 human-agent trust exploitation, ASI10 rogue agents. Mitigations for ASI07/08: authenticated identities, signed messages, replay defense, explicit who-may-talk policy, rate limits and circuit breakers at agent boundaries, blast-radius caps; for ASI06: provenance on every memory write, forgetting windows, periodic check against ground truth. · genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/ (2025) opened (release confirmed; list not on the landing page); list and mitigations from docs.modulos.ai/frameworks/owasp-top-10-agentic secondary

**F17. 2026 incidents.** OpenClaw (viral open-source local agent, Jan 2026) disclosed a one-click RCE via token theft (CVE-2026-25253, CVSS 8.8, secondary) and ClawHub supply-chain malware (secondary). Moltbook, an agent social network, exposed agent tokens and API keys; the incident tracker I opened says no injection propagation was observed, only that the design (agents ingesting other agents' posts) is a high-risk surface. · pointguardai.com/ai-security-incidents/moltbook-ai-agent-network-platform-vulnerability (2026) opened; adversa.ai and conscia.com pages via search, secondary. Treat the "memetic injection" narratives as unverified.

**F18. Deterministic out-of-band enforcement holds better than in-band detection – preliminary.** A 2026 systematisation of Dual LLM, CaMeL, FIDES, Progent and others found Progent (deterministic privilege policy) cut attack success from 25.8% to 4.2%, and to 2.6% under their adaptive attack, on a 7B model; the authors call it preliminary and leave stronger white-box attacks open. · arxiv.org/html/2606.26479v1 (2026) · opened; small lab, single model, weight accordingly

**F19. Object capabilities and the confused deputy.** Miller's thesis: in an object-capability system authority comes only from references you hold; only connectivity begets connectivity; two disjoint subgraphs cannot connect unless a bridging object introduces them; POLA grants each component only the authority its job needs; the caretaker pattern gives revocable, attenuated access. The confused deputy (Hardy 1988) is what happens when a name travels without its authority and the deputy's own authority fills the gap; capabilities bind designation and authority together. · Prevents: a peer's message borrowing the receiver's authority – exactly the injection failure restated in access-control terms. · Cost: every authority must be explicitly passed. · Miller, JHU dissertation (2006), worrydream.com/refs/Miller_2006_-_Robust_Composition.pdf opened; en.wikipedia.org/wiki/Confused_deputy_problem secondary

**F20. Attenuable bearer credentials: macaroons, Biscuit, UCAN.** Macaroons chain HMACs so any holder can append caveats that narrow when, where, by whom and for what the credential works, and can require a third party to discharge a caveat (NDSS 2014). Biscuit does the same with public-key signatures, offline attenuation by appended blocks and Datalog checks. UCAN 1.0 uses DIDs as principals; each delegation must restate or narrow its parent, invocations carry the whole proof chain, revocation invalidates downstream. · Prevents: a message carrying more authority than its task; escalation along a delegation chain. · Cost: key management, revocation propagation, token size. · research.google/pubs/macaroons-… (2014) opened (detail on caveat verification from my reading of the paper's design, secondary); github.com/eclipse-biscuit/biscuit opened; github.com/ucan-wg/spec opened

**F21. Lattices as the formal knowledge boundary.** Bell-LaPadula (1973): no read up, no write down, with trusted subjects the only ones allowed to declassify. Biba (1977), its integrity dual: no read down, no write up – a high-integrity subject must not be corrupted by low-integrity input. Denning (1976) generalised both to a lattice of classes with flows allowed only upward and joins on combination. Myers & Liskov's decentralized label model (SOSP 1997): labels are owner–reader sets, joins combine them, and only an owner can declassify its own data. FIDES and CaMeL are these ideas reimplemented for agents. · Prevents: laundering untrusted or secret data through intermediate computation. · Cost: label creep (everything drifts to top). · cs.cornell.edu/andru/papers/iflow-sosp97/ opened; BLP and Biba Wikipedia secondary; Denning CACM 1976 unverified (ACM page refused)

**F22. Defense cross-domain machinery: transform low, verify high, one-way between.** NCSC's import pattern puts a transformation engine on the untrusted side (turns complex formats into simple ones, assumed compromisable), a protocol break and one-way flow control, then a verification engine on the trusted side that checks only syntax and semantics against a narrow expected format. In April 2026 NCSC deprecated the import/export patterns for new designs in favour of a pipeline of control points across zones of trust, with six principles including transfer only what is necessary, treat all data as untrusted, only export understood and expected data, minimise the impact of compromised components, keep key controls simple, design for observability. · Prevents: a complex parser on the trusted side being the attack surface. · Cost: loss of format richness; extra stages. · ncsc.gov.uk/guidance/pattern-safely-importing-data (2018, reviewed 2025) opened; ncsc.gov.uk/blogs/new-cross-domain-guidance-… (21 Apr 2026) opened; ncsc.gov.uk/collection/cross-domain/cross-domain-design-principles opened

**F23. Content disarm and reconstruction.** Rather than detect malware, CDR parses a file against its specification, discards everything not approved by policy, and rebuilds a clean copy; it works on zero-days because it never needed to recognise the attack. · Prevents: unknown payloads riding in permitted containers. · Cost: lost functionality (macros, embedded objects). · en.wikipedia.org/wiki/Content_Disarm_and_Reconstruction (secondary)

**F24. Mail quarantine: states, release rights, detonation.** Microsoft Defender quarantine policies give three recipient permission sets: no access, limited (may request release, which alerts admins), full (may release). For malware and high-confidence phishing, users can never self-release regardless of policy; a release setting silently becomes request-release. Safe Attachments detonates attachments in a VM (typically under 15 minutes); Dynamic Delivery delivers the body immediately with placeholders for attachments until the verdict. Password-protected attachments sit in quarantine; a user supplying the password triggers a fresh detonation, and a still-unscannable item stays for an admin. · Prevents: the recipient – the person the attacker is persuading – being the one who releases. · Cost: delay; admin load. · learn.microsoft.com/en-us/defender-office-365/quarantine-policies and /safe-attachments-about (2026 revisions) · opened

**F25. Triage by blast radius and reversibility.** CVSS 4.0 splits impact into the vulnerable system and subsequent systems (replacing v3's "scope"), adds attack requirements and passive/active user interaction, and optional supplemental metrics including Recovery (automatic / manual / irrecoverable), Safety and Value Density. Bezos's 2015 letter: Type 1 decisions are irreversible one-way doors and deserve slow deliberation; Type 2 are reversible and should be made fast by small groups; large organisations fail by applying the Type 1 process to Type 2 decisions. · Prevents: uniform friction (everything gated, so gates get rubber-stamped) and uniform laxity. · first.org/cvss/v4.0/specification-document (2023) opened; Amazon 2015 shareholder letter PDF (2016) opened

**F26. End-to-end placement.** Saltzer, Reed and Clark list security via encryption and delivery acknowledgement among functions that can only be completed at the endpoints; a low-level version is at most a performance aid, and the application must still check authenticity. · Implication: capability verification and release decisions are endpoint (receiver) functions; the protocol defines the fields they read, not the enforcement. · web.mit.edu/Saltzer/www/publications/endtoend/endtoend.pdf (1984) · opened

## 2. Candidate primitives

The minimal architecture, in one paragraph: every inbound message is **sealed** verbatim with a hash and filed as **untrusted data** – it can inform, never instruct. A **deterministic gate** reads only structure (schema, signature, capability token, declared effect, labels), computes an **impact tier**, and is the only component that can move an item out of quarantine, and only for tiers its policy covers. A **quarantined reader** (a model with no tools, no private data, no outbound channel) may read the prose and emit **typed, low-capacity verdicts** that can only **ratchet** the item toward more restriction. Release above the automatic tier needs an **anchor's confirmation**: a signed act by the named authority, over the sealed hash, on a channel the sender does not control, rendered to the anchor by deterministic code rather than a model summary. Unconfirmed items **expire closed**.

Quarantine states: `sealed → quarantined → assessed → {released | held | rejected}`, `held → {released | rejected | expired}`. Release authority per tier:

| Tier | Effect class (declared by sender, recomputed by receiver) | Who may release | What counts as confirmation |
|---|---|---|---|
| T0 inform | Adds a claim to the inbox; changes nothing | Gate, automatically | Valid signature + schema; claim enters the constructed layer with provenance, never the kernel |
| T1 reversible, local | Two-way door inside an already-granted, attenuated capability | Gate, automatically | Capability token valid, unexpired, within its caveats and budget |
| T2 reversible, crosses a boundary | Writes memory, touches another peer or shared state | Reconciliation or operator | Independent second sample agrees (house reconciliation), or operator word |
| T3 irreversible | One-way door: outbound send, delete, spend, kernel change | Operator only | Signed out-of-band act over hash + exact capability exercised; no model paraphrase in the loop |

| # | Primitive | Mechanism (one line) | Seeds | Verdict |
|---|---|---|---|---|

| P2 | Seal on receipt | Verbatim store + content hash before any model reads it; later decisions reference the hash (F24, house seal) | 1 | **Core** |

| P4 | Declared effect class | Sender states the requested effect class; receiver recomputes and takes the higher of the two (F25) | 3 | **Core** (field); tier-to-releaser mapping is local policy |

## 3. Mapped to house primitives

- **Constructed layer = quarantine.** The vocabulary already says a synthesis enters knowledge only through reconciliation or the operator's word. A peer message is a synthesis made by someone else's loop; T0 claims enter as constructed, T2 needs reconciliation. No new primitive; the rule is extended from memory to the inbox.
- **Seal and run = P2.** Sealing verbatim before derivation is exactly what the quarantined reader and the release confirmation need: both refer to the sealed hash, so a summary can never be the thing confirmed.
- **Anchor = the releaser.** A release is a check against something the sending loop cannot set. The out-of-band requirement is the anchor rule stated for channels. The anchor budget applies directly: an operator who is asked to confirm everything stops being outside (FIDES's confirmation-fatigue point, Bezos's Type 1 process on Type 2 decisions). Tiers exist to spend the anchor budget only on one-way doors.
- **Hook = the deterministic gate.** "A rule a script can enforce is enforced by a script" is the literature's conclusion in house words. F13 and the deployed client channel's incident are the same finding: enforcement inside the agent is advisory.
- **Proposal = an inbound request without a capability.** It describes a change and applies nothing until the owner's word. P8 is what lets a subset of proposals become T1 actions unattended.
- **Authority and demotion = per-peer tier ceiling.** A peer's unattended ceiling (how high a tier its capabilities may reach) widens on a clean receipt record and drops for thirty days when a claim is contradicted on disk. This is γ in Agent Smith's condition: a recoverable reputation is a recovery rate.
- **Receipt = assessment receipt.** The gate writes a flags block per item: sealed hash, declared vs computed tier, sensor verdicts, releaser, exit state. "Sent means read-back confirmed" becomes "released means the anchor's signed act is on disk".
- **Tension = held item past threshold.** A hold with an owner, a TTL and a conversion threshold; expiry is the resolution when nobody acts.
- **Mirror = P11.** A verbatim, hashed copy of the peer's self-description, so a rug pull shows as a diff.
- **Voice gate / register lint = outbound gate, half-built.** It checks register; P9 adds a reader-label check before the lint.
- **Kernel.** Never reachable from inbound at any tier except through a proposal the operator applies. That is Biba's no-write-up with the operator as the only trusted subject.
- **New primitives needed:** *capability* (P8: authority as an attenuable object carried with the request), *label* (P9: reader set plus integrity source on each datum), *impact tier* (P4), *ratchet* (P7: a sensor that can only tighten).

## 4. Cross-field overlaps

1. **The reader of hostile content must not hold authority.** AI security: Dual LLM and CaMeL's quarantined model (F3, F4). Defense engineering: NCSC's transformation engine sits on the low side and is assumed compromisable (F22). Formal security: Biba forbids a high-integrity subject from reading down (F21). Access control: the confused deputy is a reader that lent its authority to a name (F19). Mail: attachments detonate in a VM, not on the recipient's machine (F24). Five fields, one rule.
2. **Rebuild, do not detect.** CDR reconstructs files to spec (F23); NCSC converts complex formats to simple ones and verifies only against the simple one (F22); CaMeL and FIDES force model output into schemas and small types (F4, F5); Dynamic Delivery ships the body and holds the risky part (F24). In every case the defense does not need to recognise the attack, which is why it survives adaptive attackers that beat detectors (F7, F9).
3. **Asymmetric authority: many may raise the alarm, few may release.** Mail quarantine lets users request but never release malware (F24); Bell-LaPadula lets only trusted subjects declassify and the decentralized label model only owners (F21); Bezos reserves slow deliberation for one-way doors (F25); CVSS 4.0 scores irrecoverable impact separately (F25). The ratchet sensor is this asymmetry applied to models.
4. **Authority only narrows as it travels.** Macaroon caveats, Biscuit blocks, UCAN's restate-or-attenuate rule, Miller's caretaker (F19, F20); lattice joins only move up (F21); NCSC's transfer only what is necessary (F22); context minimisation (F6). A delegated request can never carry more than its delegator held.
5. **Containment is a population rate, not a per-message verdict.** Epidemiology's threshold in Agent Smith (F11), OWASP's circuit breakers and blast-radius caps (F16), worm propagation in Prompt Infection and Morris II (F10, F12), and the house demotion rule (recovery rate). A protocol can make recovery fast even where it cannot make infection impossible.

(An immunology parallel – innate sensing raises alarm, adaptive release needs a second, independent signal – fits overlap 3 and is Vlad's seed 4, but I did not open a source for it here; tag unverified and route to the immune thread.)

## 5. Disagreements and open questions

- **Detector optimism vs adaptive evaluation.** Morris II's detector (TPR 1.0) and Prompt Infection's tagging plus marking (0%) were tested against fixed attacks; Nasr et al. show such numbers collapse under adaptive attack. The 2026 out-of-band evaluation (F18) favours deterministic enforcement but is small and self-described as preliminary. The honest position: sensors are useful for triage and ratcheting, worthless as release authority.
- **Human confirmation is itself an attack surface.** CaMeL routes violations to the user; FIDES warns of fatigue and social engineering; OWASP lists human-agent trust exploitation (ASI09); Willison's Dual LLM names the user pasting content across. Mitigation proposed here (deterministic rendering of exactly what is being released, tiering to save the anchor budget) reduces but does not remove it. Open: what does a T3 confirmation screen show so that the attacker's prose cannot shape the decision?
- **Text-to-text attacks remain.** Nothing in CaMeL or FIDES stops a peer's message from lying in its content. Quarantine governs what a message may *do*; whether its *claims* are true is a reconciliation and reputation problem (seeds 4, 11), not a gate problem.
- **Utility cost is real.** CaMeL loses 7 points on AgentDojo; FIDES trades utility too. A protocol that forces all peer requests to T2/T3 without capabilities will feel slow; P8 is how it earns speed, at the cost of key management and revocation.
- **Where does enforcement live?** The end-to-end argument puts release and capability checks at the receiving endpoint. That means the protocol can only *require* a deterministic gate, not provide one. Can compliance be attested (receipts that show a gate ran) without trusting the peer's word? Possibly via the peer's signed receipts plus demotion on contradiction.
- **Declared vs computed tier.** The receiver must not trust the sender's effect class, but it needs a deterministic mapping from request structure to effect. For free-form requests that mapping requires a model, which reintroduces the problem. Candidate answer: an action-selector menu (F6) – requests must name an effect from a closed vocabulary, anything else is T3 by default.
- **Label creep.** Reader-set joins drift toward "nobody may read", which pushes operators to declassify by habit. Unsolved in the IFC literature for agents.
- **NCSC's 2026 shift** from boundary appliances to pipelines of control points argues against a single gatekeeper agent (seed 2) in favour of several narrow control points (seal, schema, capability, label, rate). The seed's "intelligent gatekeeper" may be better read as a pipeline whose one intelligent stage has no authority.
- **Blockchain (seed 10)** is not needed for anything in this thread: capability chains (UCAN, Biscuit) give verifiable delegation provenance without consensus. A shared ledger would only matter for public revocation or reputation, which belongs to another thread.
