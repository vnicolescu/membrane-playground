Membrane gate explorer

An explainer, not the reference gate. This page is a simplified model of the 21-step gate in gate.js (contract 0.3-draft, commit 2ca3d45), built by reading that code as text. Its notes and prose are in our own words; step ids, reason codes, params and field names are the repo's. It does not load or run gate.js, makes no network calls and keeps no data. If this page and Gate.evaluate ever differ, trust Gate.evaluate. Each envelope comes with its inputs stated as facts (for example "sensor label: impact high") rather than worked out from its bytes.

    Sources attached to the claim
    
   
    An agent asserts "the project moved to its next phase" with evidence: reconciled, and that agent is also who sent it. Switch sources on or off.
    
  
    
  
    
   
    Counting distinct signers
    
   
    
     
     
     
   
    
   
    
   
    
   
    
   
    The rule, in our words
    
   
    L6: anything with real consequences is let out only on two signals
    that are independent, the second from somewhere that could not
    have made the first.
ev.reconciled: every source has to carry a signature from someone
    who is not the sender; if not, the claim is treated as synthesis.
(Exact wording: spec.js, and ARCH.md §7.)

Our reading of step 17 (evidence) in gate.js:
distinct signers = signers of the sources, minus the sender, minus bad signatures
2 or more      → admitted as a fact
else, a second signal on hand → admitted
else           → held, reason awaiting-signal (treated as synthesis)
    
  
    
  
    
   
    Why two reports from one system are one party
    
   
    Take any single system of record. Its audit report, its daily export, its webhooks and its saved-report pulls all come from one producer. The gate counts distinct signers, so any number of documents from that system makes a set of one.
    
   
    What follows
    
   
      
    
    • Count parties, not documents. Two reports out of one vendor count once.
      • 
    
    • A system of record is a usable signal 2 next to an agent's own claim, since the agent cannot make that system's records.
      • 
    
    • The side under check cannot vouch for itself. The ledger, and receipts from the ledger's own writer, belong to the claim, not to an anchor; dropping the sender's signatures takes them out.
      • 
    
    • One more, unrelated party (a mail provider for outward effects, a public registry for filings) brings the set to two. confirm per deployment.
      • 
   
    
   
    The contract only asks that each signer is someone besides the sender; gate.js also wants the two signers to be different from one another. confirm which reading the contract means.
    
  
    
 
    

    


    
 
    
 
    About this explainer
    
 
      
  
    • What it is. A teaching model of the step order, codes and release rule, from our reading of gate.js and as set out in ARCH.md §5 to §7. One static file: no network, no model calls, no storage, no libraries.
      • 
  
    • What it is not. The reference gate. It parses no bytes, checks no hashes, does no sensor scoring and does not read spec.js. Inputs like "pointer matched" or "sensor label: impact high" are stated per envelope as facts.
      • 
  
    • Where the presets come from. The 13 scenarios in spec.js and the scripts in sim.js (message bodies paraphrased), plus one envelope per evidence kind and one known gap (the gate does not check env.state yet). Each preset's expected result comes from test-vectors/, written from the text and since run against the gate with test-vectors/run.js. The line below the outcome says how many presets this model agrees with.
      • 
  
    • The break knob on a preset is that scenario's break from spec.js, or, for the four scenarios with break: null, the rule we propose in docs/proposals/scenarios-breaking-rules.md (marked proposed).
      • 
  
    • Simplifications. Only alerts get a page decision. Holds, rate and turns used so far are given as numbers. A duplicate returns what was kept with the first copy (its disposition and whether a receipt was owed). confirm that none of this misstates the gate.
